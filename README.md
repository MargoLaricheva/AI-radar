# AI Radar

Персональный AI-радар присутствия в Telegram-сообществах.

Следит за выбранными чатами через ваш аккаунт (MTProto), анализирует **разговоры** (не отдельные сообщения), находит возможности — от горячих лидов до обсуждений, где уместно показать экспертизу — и присылает карточки с рекомендациями в личный чат Telegram-бота.

**Важно**: это self-hosted инструмент для одного пользователя. Использование личного аккаунта для автоматизированного чтения чатов — серая зона ToS Telegram; риск бана аккаунта существует. Система смягчает его лимитами, задержками и kill switch, но не устраняет полностью.

## Возможности

- 🔍 Мониторинг до 100 чатов через ваш аккаунт (QR-вход, событийный поток, догон после простоя)
- 🧠 Анализ диалогов: сегменты + долгоживущие треды (диалог может растягиваться на часы/сутки), детекция дрейфа темы
- 🎯 Два трека сигналов: **клиенты** (запуск, хостинг, разработка) и **экспертиза** (обсуждения инструментов, где уместно участие)
- 📇 Карточка: суть, тезисы, шанс на клиента %, готовый текст «что написать», «что не писать»
- 👍👎 Обучение: лайк повышает приоритет темы/чата, дизлайк — исключает; 2 дизлайка на тему — blacklist
- 📚 `/teach` — пришлите пример (текст/пересылку), система сохранит якорь и будет находить похожее
- ✅ Авто-трекинг: ответили в чате — карточка сама станет «Вы ответили», пойдёт диалог — «Диалог идёт»
- 📊 Ежедневный дайджест, тихие часы, уровни уведомлений, kill switch
- 🔒 Сессия шифруется (AES-256-GCM), retention 30 дней, расходы LLM в `/stats`

## Установка

Требования: Linux-сервер с Docker (или локально: Bun ≥1.2, PostgreSQL 16).

1. Клонируйте репозиторий и создайте `.env`:
   ```bash
   cp .env.example .env
   chmod 600 .env
   ```
2. Заполните обязательные поля:
   - `BOT_TOKEN` — токен бота из [@BotFather](https://t.me/BotFather)
   - `LLM_API_KEY` — ключ LLM (OpenAI-совместимый; по умолчанию opencode go, base `https://opencode.ai/zen/go/v1`, модель `deepseek-v4-flash`)
   - `OWNER_ID` — ваш Telegram user_id (можно не заполнять — привязка произойдёт по первому `/start`)
3. Запуск:
   ```bash
   docker compose up -d --build
   docker compose logs -f app
   ```
4. В логах появится QR-код (или он придёт в бот). Отсканируйте: **Telegram → Настройки → Устройства → Сканировать QR**.
5. Напишите боту `/start` — вы станете владельцем.
6. `/profile_edit` — заполните профиль (чем занимаетесь, услуги, ниши).
7. `/chats` — включите чаты для мониторинга.

## Команды бота

| Команда | Действие |
|---|---|
| `/chats` | выбор чатов (кнопки вкл/выкл) |
| `/history` | прошлые заявки (пагинация, открытие карточки) |
| `/card <id>` | открыть карточку по номеру |
| `/digest` | дайджест сейчас |
| `/profile`, `/profile_edit` | просмотр/редактирование AI-профиля |
| `/settings` | уровень уведомлений, тихие часы, kill switch |
| `/teach` | сохранить пример «вот такое тоже находи» |
| `/pause` `/resume` | пауза уведомлений |
| `/stats` | счётчики и расход LLM за сутки |
| `/status` | состояние аккаунта и системы |

## Настройки (переменные окружения)

Все параметры — в `.env` (см. `.env.example`): лимиты анализа, порог фильтра, тихие часы, retention, уровень уведомлений и т.д.

## Разработка

```bash
bun install
bun run check        # typecheck
bun test             # тесты (нужна локальная Postgres: DATABASE_URL_TEST)
bun run db:generate  # миграции из схемы
bun run db:migrate   # применить
bun eval/golden.ts   # eval-прогон фильтра (отчёт в eval/report.md)
bun src/index.ts     # локальный запуск
```

## Ограничения v1

- Один пользователь, один Telegram-аккаунт.
- Нет автоотправки ответов (только готовые тексты для копирования).
- Мегачаты-флуд (5k+ сообщений/день) автоматически отсекаются.
- LLM: один провайдер (OpenAI-совместимый); для фильтра — локальные embeddings.

## Устранение проблем

- **«Insufficient balance»** — пополните баланс LLM-провайдера (аккаунт opencode).
- **«Требуется повторный вход»** — сессия протухла: удалите `tg_accounts` в БД, перезапустите, отсканируйте новый QR.
- **Чаты не приходят** — проверьте `/status`, что аккаунт подключён, и что в чатах есть активность.
- **FloodWait** — система сама ждёт с бэкоффом; при длительных лимитах чат помечается и исключается.
